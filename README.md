# Dauntless Private Server (experimental)

This repository is an independent, clean-room learning project. It currently provides a small local FastAPI service and read-only binary string-analysis utilities. It is **not a finished Dauntless server**, is not endorsed by Phoenix Labs or Epic Games, and has not been shown to interoperate with a retail game client.

## Setup and run

Python 3.11 or newer is recommended.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m uvicorn src.main:app --host 127.0.0.1 --port 8000
```

Open `http://127.0.0.1:8000/docs` for the API schema generated by the installed build. Configuration uses `DPS_`-prefixed environment variables such as `DPS_PORT`, `DPS_DATABASE_PATH`, and `DPS_SESSION_TTL_SECONDS`.

## Optional PlayFab integration

The backend can link an authenticated local account to a PlayFab player in a title you own. It is disabled unless both `DPS_PLAYFAB_TITLE_ID` and `DPS_PLAYFAB_SECRET_KEY` are configured. Copy `.env.example` to an ignored `.env`, use development credentials, and keep the title secret on the server only. The integration exposes authenticated status/link routes under `/integrations/playfab`; it never returns or stores PlayFab session/entity tokens.

See [PlayFab research](docs/PLAYFAB_RESEARCH.md), [configuration](docs/PLAYFAB_CONFIGURATION.md), and [multiplayer architecture](docs/PLAYFAB_MULTIPLAYER.md). This integration does not connect the retail Dauntless executable or impersonate its PlayFab/Epic environment.

## Scope

The first usable milestone is a local HTTP proof of concept: health/status, local accounts and sessions, and limited simulated gameplay data where wired into the application. The OpenAPI document is the source of truth for routes actually available. Research notes describe hypotheses and future work; they are not protocol specifications.

Run tests with `python -m pytest -q` after installing the development/test dependencies required by the current branch. See [TESTING.md](TESTING.md).

## Read-only analysis tools

Each tool requires an explicit file path and supports `--help`:

```powershell
python extract_strings.py path\to\binary.exe
python extract_endpoints.py path\to\binary.exe
python find_endpoints.py path\to\binary.exe
python find_config.py path\to\binary.exe --config path\to\Settings.json
```

Results are string candidates, not proof that an endpoint is used. Only inspect files you are authorized to analyze. The tools stream input and bound output, but a very long uninterrupted printable byte sequence can still consume memory.

## Boundaries

This project does not provide DLL injection, Epic service impersonation, credential/token interception, DRM circumvention, or Easy Anti-Cheat bypass. It does not ship proprietary assets, keys, or protocols. Official service integrations must use products and credentials owned by the operator and remain subject to their providers' terms.
