# Dauntless Private Server (experimental)

This repository is an independent clean-room protocol-research project whose goal is to identify the service calls and Unreal game-server contract expected by the December 2024 Dauntless client, then build evidence-backed compatible components. It currently provides a local FastAPI control-plane prototype plus read-only static and capture-analysis utilities. It is **not a finished Dauntless server**, is not endorsed by Phoenix Labs or Epic Games, and has not yet been shown to interoperate with a retail game client.

The current evidence points to a layered runtime flow: Phoenix matchmaking, Unreal party-beacon reservation/reconnect, Unreal travel, then an authoritative ReplicationGraph/RPC session. See the [static service-call inventory](research/STATIC_SERVICE_CALLS_2026-09-20.md) and [Unreal game-server evidence](research/UNREAL_GAME_SERVER_STATIC_EVIDENCE.md). Exact production HTTP routes, request bodies, travel destination, admission handshake, packet layouts, and replicated schemas still require version-matched runtime evidence.

## Setup and run

Python 3.11 or newer is recommended.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m uvicorn src.main:app --host 127.0.0.1 --port 8000
```

Open `http://127.0.0.1:8000/docs` for the API schema generated by the installed build. Configuration uses `DPS_`-prefixed environment variables such as `DPS_PORT`, `DPS_DATABASE_PATH`, and `DPS_SESSION_TTL_SECONDS`.

## Experimental PlayFab adapter

The backend includes an optional experiment that can link an authenticated local account to a PlayFab player in a title you own. It is not a recovered Dauntless call contract and is not the game-server transport. It is disabled unless both `DPS_PLAYFAB_TITLE_ID` and `DPS_PLAYFAB_SECRET_KEY` are configured. Copy `.env.example` to an ignored `.env`, use development credentials, and keep the title secret on the server only.

See [PlayFab research](docs/PLAYFAB_RESEARCH.md), [configuration](docs/PLAYFAB_CONFIGURATION.md), and [multiplayer architecture](docs/PLAYFAB_MULTIPLAYER.md). This integration does not connect the retail Dauntless executable or impersonate its PlayFab/Epic environment.

## Scope

The HTTP service is a control-plane proof of concept for health, local accounts/sessions, and limited simulated data. It does not implement Unreal networking. Protocol work must promote a behavior from hypothesis to implementation only after a version-matched call site, log, redacted authorized capture, or wire trace confirms it.

Run tests with `python -m pytest -q` after installing the development/test dependencies required by the current branch. See [TESTING.md](TESTING.md).

## Read-only analysis tools

Each tool requires an explicit file path and supports `--help`:

```powershell
python extract_strings.py path\to\binary.exe
python extract_endpoints.py path\to\binary.exe
python find_endpoints.py path\to\binary.exe
python find_config.py path\to\binary.exe --config path\to\Settings.json
python analyze_capture.py path\to\authorized-session.har --output call-map.json
```

Results are string candidates, not proof that an endpoint is used. Only inspect files you are authorized to analyze. The tools stream input and bound output, but a very long uninterrupted printable byte sequence can still consume memory.

The offline capture importer accepts authorized HAR and tshark JSON/CSV exports,
emits names and schemas rather than secret values, and performs no interception.
See [offline HTTP call-map analysis](docs/CAPTURE_ANALYSIS.md).

## Boundaries

This project does not provide DLL injection, Epic service impersonation, credential/token interception, DRM circumvention, or Easy Anti-Cheat bypass. It does not ship proprietary assets, keys, or protocols. Official service integrations must use products and credentials owned by the operator and remain subject to their providers' terms.
