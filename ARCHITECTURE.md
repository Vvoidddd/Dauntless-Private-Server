# Architecture

The implemented core is a single Python/FastAPI process. `src.main` owns application composition and HTTP routing; `src.config` reads isolated `DPS_` settings; `src.models` defines API schemas; `src.db` and `src.security` provide local persistence and session/password primitives. `src.gameplay` contains a limited simulated domain service and router where integrated.

SQLite is appropriate for the local milestone and tests. It is not a production multiplayer datastore. HTTP is the only implemented transport covered by this document; Unreal replication, EOS, PlayFab compatibility, matchmaking infrastructure, and authoritative real-time game simulation remain outside the verified architecture.

Dependencies should flow from routes to service functions and then persistence/security helpers. Tests should use temporary databases and dependency/application factories rather than shared user data. OpenAPI generated by the running application is authoritative when older research documents disagree.

The top-level scanner scripts are separate, read-only offline utilities. They stream binary input, extract printable ASCII candidates, and never modify the inspected client file.
